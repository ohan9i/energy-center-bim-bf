# 현장 사진을 반영한 외관 보완

2026-10-12, revision 10 / modelling_version 13. 사용자의 실제 건물 외관을 사진으로 대조하여 비슷하게 만들라는 요청에 따른 작업이다.

## 사진 출처와 건물 식별

주 근거는 [광주테크노파크·I-PLEX의 2026 창업기업제품 실증지원사업 공고](https://www.iplexgj.com/board/B0002.cs?act=read&bwrId=723)에 첨부된 **혁신기술수요조사서**다. 4쪽에는 실증 대상 주소가 광주 남구 도시첨단산업6로 2로 명시돼 있고, 5쪽에는 옥외 PV와 외벽 BIPV의 실제 사진 4장이 있다. 파일 SHA-256은 `d6439b9a6bd1c2c2832df4ed318c9487d2161762140210297a28302e329340a7`이다. 사진 촬영일은 명시돼 있지 않다.

추가로 [광주시의 개관 안내](https://blog.naver.com/dodreamgj/223382179868)와 [당선작 발표](https://www.nocutnews.co.kr/news/5491722)의 조감도를 참고했다. 이 둘은 **준공 사진이 아니다**. 지붕 위 설비의 전반적인 구성과 외장 방향을 보조적으로 읽었으며 현장 시공 상태의 증명으로 사용하지 않았다. 검색에 섞여 나온 새만금·경북 센터와 별도의 광주 에너지 지식산업센터는 제외했다.

원본 사진과 PDF는 로컬 `cad_output/photo-reference-2026-10-12/`에 보존하고 웹에 재게시하지 않는다. 웹 객체의 사진 출처 링크는 운영기관의 공고로 연결한다.

## 반영한 외관

- 현장 사진의 밝은 상부 외벽과 짙은 회색 하부 외벽을 적용했다. 기존 부재 중 CAD 바닥 외곽에 인접한 벽·기둥·보의 표현 재료를 변경하며, 이전 표현 재료는 구성요소의 `pre_photo_material`에 남겼다. 사진에서 제품명이 확인된 것은 아니므로 재료 규격 승인으로 처리하지 않는다.
- 불연속으로 추출된 외곽에는 약 58mm 깊이의 외장 표현을 추가했다. 기존 문과 창의 위치 및 높이 범위에 맞춰 절단한다. 외장 깊이는 실측값이 아니다.
- 상부 돌출부의 큰 남색 BIPV 격자와 긴 외벽의 창 사이 패널을 추가했다. 분할 치수와 개별 패널의 배정 범위는 추정이다. 기존 창호 조립체의 위치와 A10 규격은 유지한다.
- 사용자 후속 지시에 따라 **옥상·외부 대지의 PV 패널은 제외**했다. PV를 위해 추가했던 외부 캐노피와 지지 구조도 제거했다. 생성기에서도 해당 형상을 만들지 않으므로 전체 재생성 시 다시 추가되지 않는다. 원래 건물 부재와 외벽 BIPV는 유지한다.
- 웹과 검토 IFC에서 같은 표현 재료 색상을 사용한다. 사진 기반 객체는 기존 층·단면·선택 기능을 따르며, 속성에는 사진 출처와 치수·배치의 추정 상태를 표시한다.

## 근거와 추정의 차이

사진에서 외벽이 밝다는 사실을 읽을 수 있어도, 마감판 두께나 앵커 간격은 알 수 없다. 원근 때문에 사진의 창 폭을 픽셀로 재어 실제 mm 치수로 바꿀 수도 없다. 따라서 현재 작업은 **CAD 위치에 사진의 외장 구성을 등록한 외관 검토 모델**이다. 현장 실측으로 만든 준공 BIM, 설계 승인, 구조 검토 또는 BF 인증 결과가 아니다.

사진 참조는 `source.photo_reference`, 기존 부재의 표현 변경은 `source.photo_appearance`, 전체 변경 원장은 `provenance.photo_exterior`와 로컬 `photo-exterior-validation.json`에 남긴다. 추가 형상은 사용자 허용 추정이며 `verified`를 켜거나 검증 IFC에 미확정 입체를 넣지 않는다. BF 공간 자료는 모델 변경에 맞춰 갱신하되 실제 통행 승인을 새로 부여하지 않는다.

## 검사와 배포

최종 모델은 **3,599개 객체, 8,040개 구성요소**다. 기존 2,998개 객체의 다각형·구멍·높이·Z·삼각망은 revision 9와 동일하다. 1,164개 객체의 외곽 부재 표현 색상을 변경했고 외장·BIPV 객체 601개를 추가했다. 개수 증가를 정확도 향상의 지표로 사용하지 않는다. 옥상·외부 PV와 PV 캐노피·지지대 구성요소는 0개다.

모든 검토 IFC 객체와 입체 구성요소의 형상·체적·세계 좌표를 검사했다. EXPRESS 오류는 0건이며 JSON/IFC 좌표의 최대 계산 차이는 약 `3.330e-7m`다. 이 수치는 **파일 변환의 수치 일치**로, 현장의 시공 오차가 아니다. 검증 IFC는 미확정 입체를 포함하지 않으며 검증 완료 입체는 0개다. 외장과 기존 기둥의 교차부는 외장 쪽에서 잘라내고 기존 문·창 개구부를 유지했다.

공간 경계 31개는 미확정이며 실제 BF 성공 경로를 새로 승인하지 않는다. 기존 벽체 후보 44개의 원본 관측과 분류를 유지한다. 외관만 갱신하는 빠른 생성에서는 보존한 CAD 벡터 관측과 revision 9의 분류를 연결하고 재분류하지 않는다. 새 검사 결과를 저장할 때 기존 검사 원장 필드를 유지한다.

웹 테스트 67개와 TypeScript/Vite 빌드, Pages 하위 경로 자산 검사에 통과했다. 전체 CAD 모델을 읽는 테스트의 메모리 중복과 실행 시간 제한에 걸리는 사례를 확인해 Vitest 동시 작업 수를 2개로 제한하고 검사 제한 시간을 15초로 설정했다. 형상·BF의 검증 조건은 그대로 유지한다.

Chrome/WebGL에서 외관, 정면·측면·옥상, 사진 근거 속성, 층별 화면과 390/320px 모바일 등 10개 화면을 확인했다. 실행·HTTP 오류는 0건이다. 캡처와 결과는 로컬 `coordination-v2/browser-photo-exterior/`에 있다. IFC 생성 시 별도의 검토용 모델을 브라우저에 연결했고, 배포 전 최종 공개 파일과도 대조한다.

현재 CAD 재구축을 반복하지 않는 외관 보완은 `tools/rebuild_photo_exterior.py`로 수행했다. revision 9 입력의 생성기 의존성 해시와 기존 전체 부재 형상 일치를 요구한다. 정상 전체 재생성인 `python -m bf_bim.precise.rebuild --coordination --sync-web`도 같은 외관 생성기와 수치 정리를 사용하며 제외한 PV를 생성하지 않는다.
