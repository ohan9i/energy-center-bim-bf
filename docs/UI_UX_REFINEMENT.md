# 공간이음 UI/UX 개선

디자인 방향은 **Architectural Precision Workspace**입니다. CAD에서 복원한 모델을 중심으로 탐색, 객체 검토, BF 경로 설정을 같은 화면 언어로 구성했습니다.

## 참고 자료와 적용 판단

- [Autodesk Forma](https://www.autodesk.com/products/forma-building-design/overview): 건축 모델을 작업의 중심에 두는 구성에서 출발했습니다. 공간이음에서는 큰 소개 영역을 줄이고 프로젝트명·모델 상태를 짧은 작업 헤더에 배치했습니다.
- [Speckle의 뷰어 개편](https://speckle.systems/updates/redesigned-3d-web-viewer/): 카메라 도구와 모델 조작 도구를 묶는 원칙을 참고했습니다. 전체 맞춤·선택 확대·실내 시점은 바로 접근하고, 표시 설정과 단면·층 분리는 펼쳐서 조작합니다.
- [Linear의 UI 개편](https://linear.app/now/how-we-redesigned-the-linear-ui): 시각적 잡음 감소, 정렬, 정보 위계, 일관된 표면과 색상의 원칙을 참고했습니다. 절제된 청록색, 공통 높이·테두리·포커스·여백으로 적용했습니다.
- [Vercel Geist Typography](https://vercel.com/geist/typography): 용도에 따른 문자 위계와 숫자의 일관된 표시를 참고했습니다. 한국어는 Pretendard를 사용하고 숫자에는 tabular-nums를 적용했습니다. 기존 Noto Sans KR은 한국어 대체 서체로 남겼습니다.

공개 제품 자료를 검토해 공간이음에 맞게 해석한 내용입니다. 각 서비스의 로그인 후 작업 화면을 직접 비교한 결과는 아닙니다.

## 구현

| 영역 | 변경 내용 |
| --- | --- |
| 공통 디자인 | CSS 변수로 배경·표면·문자·강조·상태·테두리·전환 시간을 관리합니다. 버튼, 입력, 포커스, 비활성, 알림을 통일했습니다. |
| 작업 화면 | BIM 모델 / BF 경로 탐색을 명확한 탭으로 구성했습니다. 객체 패널과 속성 패널을 각각 접을 수 있습니다. |
| 객체 탐색 | 실제 모델의 층과 종류로 그룹화합니다. 검색, 종류 필터, 선택 상태, 사용자 검토 기록을 표시합니다. 큰 그룹은 100개씩 더 표시하며 모든 종류의 그룹은 처음부터 제공합니다. |
| 뷰어 | 차분한 배경, 중립적인 조명, 약한 윤곽선·격자와 그림자 수신면을 적용했습니다. 기존 재질 분류와 선택 강조를 유지합니다. |
| 표시 도구 | 벽체, 지붕, 실, 실명, 미확정 면, 임시 조립체를 표시 설정에 모았습니다. 단면 방향·위치와 층 분리는 별도 도구입니다. Escape 또는 도구 밖 클릭으로 닫습니다. |
| Inspector | 선택 객체 이름과 검토 상태, 기본 정보를 먼저 보여줍니다. 형상·구성 요소, CAD 근거, 조립체, 상세 원본 데이터를 접어서 확인합니다. 필요한 도면과 미확정 정보는 보존했습니다. |
| BF | 동일한 디자인 시스템으로 출발지·목적지·이동 조건과 결과를 구성합니다. 거리, 시간, 이동 층, 제외 근거, 검증 한계를 보존합니다. |
| 반응형 | PC는 세 영역, 태블릿은 측면 패널, 휴대폰은 하단 패널입니다. 모델 크기를 유지하고 패널 내부에서 스크롤합니다. |
| 접근성 | 아이콘 버튼에 이름·툴팁, 선택·펼침 상태, 포커스 표시를 제공합니다. 숨겨진 패널은 inert를 적용합니다. 편집창은 Tab 포커스 순환과 Escape 닫기를 지원합니다. 움직임 감소 설정을 따릅니다. |

PC에서 객체 패널의 오른쪽 아래 모서리를 드래그하면 너비를 조절할 수 있습니다. 모바일의 도구는 아이콘으로 표시되며 각 버튼의 접근성 이름은 유지합니다.

## 보존 범위

`model.ts`, `geometry.ts`, `bimGeometry.ts`, `evaluation.ts`, `navigation.ts`, `route.worker.ts`, `modelStorage.ts` 및 CAD/Python 구현과 모델 JSON은 변경하지 않았습니다. 층 분리와 렌더링 옵션은 표시 상태입니다. 검증되지 않은 치수·조립체·사용자 검토 기록을 공식 BF 인증 또는 확정된 건축 정보로 표현하지 않습니다.

## 검증 방법

2026-10-10 검증 결과: 웹 테스트 26개, Python 테스트 18개, CAD 리더 테스트 6개를 통과했습니다. 일반 빌드와 Pages용 이용자 빌드를 확인했습니다. 네 가지 해상도의 브라우저 검사에서 가로 넘침과 JavaScript 실행 오류는 없었으며, 모바일 헤더·프로젝트 영역의 겹침도 수정 후 재검사했습니다. 예제의 휠체어 경로는 모든 해상도에서 32.6 m, 71초, 승강기 이용으로 동일했습니다. 객체 편집창의 Escape 닫기도 검사했습니다.

```powershell
cd web
npm.cmd test
npm.cmd run build
```

브라우저 QA 스크립트는 `web/scripts/ui-qa.mjs`입니다. 별도 테스트 브라우저를 열기 때문에 사용자의 브라우저 저장 모델을 사용하지 않습니다. Chrome과 Playwright가 필요합니다. 프로젝트 의존성을 변경하지 않고 별도 디렉터리에 설치한 Playwright를 사용할 수 있습니다.

```powershell
npm.cmd install --prefix "$env:TEMP/spatial-bim-qa" playwright --no-audit --no-fund
$env:UI_QA_MODULE = "$env:TEMP/spatial-bim-qa/node_modules/playwright"
node scripts/ui-qa.mjs
```

로컬 앱이 `http://127.0.0.1:5173/`에서 실행되어 있어야 합니다. 다른 URL은 `UI_QA_URL`로 설정합니다. 검사 대상은 1920×1080, 1440×900, 768×1024, 390×844입니다. 스크린샷과 측정 결과는 Git에서 제외된 `.runtime/ui-qa/`에 생성됩니다.

브라우저 검사에서는 화면의 가로 넘침, 뷰어 높이, 표시 옵션, 단면·층 분리, 층 전환, 객체 선택·속성 표시, 이동 조건, 예제의 경로 성공, JSON 내보내기 시 ID·평면 다각형·높이·개정값 보존, JavaScript 실행 오류를 확인합니다. 실제 건물의 BF 통행 가능 여부를 검증하는 시험은 아닙니다.

서체는 CDN에서 로드하며 연결이 없으면 시스템 대체 서체를 사용합니다. Three.js의 기존 2048 그림자 맵과 최대 2배 픽셀 비율을 유지하고 무거운 후처리 효과는 추가하지 않았습니다. 테스트용 브라우저는 소프트웨어 WebGL을 사용하므로 실제 기기의 GPU 성능을 대표하지 않습니다.
