# 건물 전체 3D 정합성 개선 계획과 실행 기록

2026-10-14 계획, 2026-10-15 실행 마무리. 기준은 작업 폴더의 revision 10 / modelling_version 13이며 결과는 revision 11 / modelling_version 14다. 기존 미커밋 작업과 원본 DWG, 도면 추출 캐시는 보존한다.

## 실행 계획

1. 현재 모델의 실제 XYZ 형상으로 외피 개구부, 지붕 경계, 슬래브 접합과 계단 참 연결을 검사한다. 객체 수와 IFC 형식 검사만으로 완성도를 판단하지 않는다.
2. 창·문을 사방으로 부풀려 외장을 자르던 처리를 창·문 축에 직각인 깊이 방향 투영으로 교체한다. 꺾인 창은 각각의 실제 축을 사용하고 개구부 높이를 유지한다.
3. 지붕 파라펫은 지붕 외곽과 중정 경계에 연결하고, 내부 미확정 구멍 주변에 자동 생성되는 파라펫을 제거한다. 접하는 기존 부재는 실제 높이 구간으로 판단한다.
4. 외장과 상층 슬래브의 교차부를 XYZ에서 정리하고 기존 옥탑 벽과 덮개 접합도 검사한다. 도면에서 관측한 문·창·기둥의 평면은 유지한다.
5. 건물 전체 수치 검사와 코어 종·횡단면을 생성한다. 전체·사방·지붕·1층·코어·단면의 실제 3D 캡처를 직접 보고 수정한다.
6. 관련 회귀 테스트, Python 전체 검사, 웹 검사·빌드, IFC의 실제 입체·체적·좌표 검사를 수행한다. 최신 모델 하나에 적용하며 이전 모델을 웹 목록에 복원하지 않는다.

## 완료 판단과 한계

- 개구부 폭을 임의로 넓히지 않고 모든 개구부의 높이 구간에서 불투명 외장을 검사한다.
- 의도하지 않은 슬래브 중복 체적과 파라펫의 경계 이탈을 전후 수치로 비교한다.
- 계단 참의 위층 바닥 레벨·평면 접촉을 별도로 보고한다. 미접촉을 통행 승인으로 해석하지 않는다.
- 단면은 현재 모델의 실체 검사다. 원본 입면·단면과의 독립적인 부재 배정, FFL/SSL, 누락 구조 XREF, 옥탑 600mm 레벨 충돌은 별도 검토 대상이다.
- 추정 외장 깊이·파라펫 높이를 실측값이나 설계 승인으로 승격하지 않는다. 실제 BF 경로 승인도 생성하지 않는다.

## 실제 수정

- `envelope.py`에서 실제 창호 축의 폭을 유지하는 깊이 방향 투영을 구현했다. 꺾인 창은 각 구간별로 절단한다. CAD 원본 축과 1mm로 반올림된 기존 심볼 사이의 얇은 잔여도 기존 심볼 윤곽을 함께 보존하여 제거한다. 사방 200/220mm 버퍼로 개구부를 넓히지 않는다.
- `photo_exterior.py`에서 외장과 BIPV를 개구부의 전체 높이 구간에 맞춰 절단한다. 프레임만의 높이가 아닌 기존 개구부 레벨을 사용한다. 내부 문이 외벽을 잘라내지 않도록 기존 외곽 근접 조건(550mm)을 적용한다. 패널 치수나 실제 BIPV 설계 배정을 확정한 것은 아니다.
- 사진 외장 추가 **후**에도 슬래브 우선 XYZ 교차 절삭을 실행한다. 이전에는 이 단계 뒤에 추가된 외장이 상층 슬래브와 중복됐다. 기존 본체의 수치 허용오차 잔여는 보존하며 새 외장을 정리한다.
- 파라펫은 지붕 외곽과 명시된 중정 경계에만 배치한다. 내부 분할·미확정 구멍의 경계를 파라펫으로 만들지 않는다. 기존 부재와의 접촉은 실제 높이 구간으로 검사한다. 파라펫 객체는 60개에서 8개로 통합되지만, 개수 자체는 정확도의 지표가 아니다.
- `Viewer.tsx`의 선택 확대가 출입문 축을 사용하고 양쪽의 불투명 장애물을 비교하도록 수정했다. 고정 사선으로 카메라를 배치해 선택한 문이 이웃 벽에 가려지던 실제 화면 문제를 해결했다.
- `building_review.py`의 검사 조건을 전체 생성기에도 넣었다. 외피 개구부 불투명 잔여, 슬래브 교차, 외장 틈과 파라펫 경계 이탈이 한계를 넘으면 모델 생성이 실패한다. 종·횡단면과 계단 단면은 실제 구성요소 삼각망을 절단한다.

## 시각 검사와 재현

Chrome 실제 WebGL에서 전체 사선·사방·상부, 1층/3층/지붕, 두 방향 단면, 출입구 주변과 실내, 390/320px 모바일을 확인했다. 캡처를 직접 검토해 선택 확대 카메라 문제를 수정했다. 첫 번째 개선 모델의 캡처 폴더 이름 `browser-building-3d-before`는 revision 11 중간 결과이며 revision 10 비교본으로 사용하지 않는다. revision 10 외관 캡처는 기존 `browser-photo-exterior/` 기록이다.

현재 결과는 `cad_output/precision-rebuild/coordination-v2/` 아래에 있다.

- 수치 원장: `building-3d-review.json`, `building-3d-comparison.json`
- 전체/코어/계단 단면과 절단 위치: `building-3d/*.png`, `building-3d/sections.json`
- 실제 최종 화면: `browser-building-3d/*.png`, `browser-building-3d/results.json`
- IFC 검사: `validation.json`; 원본 보존: `preservation.json`

```powershell
.\.venv-cad\Scripts\python.exe -m bf_bim.precise.rebuild --coordination --sync-web
.\.venv-cad\Scripts\python.exe -m tools.building_3d_review
.\.venv-cad\Scripts\python.exe -m tools.building_section_review
.\.venv-cad\Scripts\python.exe -m pytest tests -q
npm.cmd --prefix web test
```

최종 수치 잔여 보완은 원본·strict-stage 해시를 확인하는 `tools/rebuild_photo_exterior.py`로 보존된 revision 9의 본체에 같은 외피/파라펫 생성기를 적용했다. 정상 전체 재생성에도 같은 최종 연산을 적용한다. 빠른 생성은 원래 본체 형상이 정확히 보존되는지 추가 검사한다. 이전 모델을 공개 목록에 추가하지 않는다.

| Python 전체 회귀 검사 | 117개 통과, 기존 Starlette/httpx 경고 1건 |
| 웹 회귀 검사 | 67개 통과 |

Windows 샌드박스의 임시 폴더/경로 확인/로컬 HTTP 제한으로 중단된 검사는 권한을 받아 다시 실행했다. 모델의 잘못된 반올림 잔여를 잡은 회귀 검사는 생성기를 보완하고 동일한 검사 기준으로 통과했다. 검사 한계를 완화하지 않았다.
