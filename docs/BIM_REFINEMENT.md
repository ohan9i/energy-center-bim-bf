## 실제로 변경한 내용

이전 모델은 지상 1·2층의 820개 객체였습니다. 벽체를 합쳐 압출하고, 실명은 장소로만 저장하며, 바닥에는 중정이 채워져 있었습니다. 창호가 벽체로 분류되고 계단은 한 코어만 덩어리로 표현됐습니다.

현재 모델은 **지하 1층·지상 1~4층·지붕/옥탑 후보, 2,278개 객체, 46개 장소**입니다. 객체 개수는 실제 건축 부재 수량과 다릅니다. 벽면 표시·창호 프로파일·분리된 바닥 영역 등 재구성 후보가 포함됩니다.

## 도면과 좌표 근거

평면도와 보조 DWG 총 **16개**를 실제 리더로 조사했습니다. 입면·단면·코어·창호뿐 아니라 외벽 상세, 확대 평면, 출입구 상세, 창호 상세, 실내 마감표와 하위 폴더의 구조 평면·단면·확대 평면·기둥/계단/벽체 일람표를 포함합니다. `cad_output/*-evidence.json`에는 객체 형상·문자·단위·해시·변환 경고가 있습니다. 추출은 임시 복사본에서 수행하며 원본 저장·복구 작업을 하지 않습니다. 생성기는 해시가 바뀐 캐시를 거부합니다.

구조 도면에는 `s-xref-plan`, `s-xref-section` 본체의 미제공 참조가 확인됩니다. 부재 부호와 일람표가 읽힌다는 사실만으로 보의 위치·길이·높이나 슬래브 영역을 확정할 수 없어 임의 배치하지 않았습니다. 기둥 일람표에서 C1=600×600, C2=500×600, C3/C4=500×500, C5=500×400, C6=Ø500 mm를 추출했습니다. 평면 기둥 178개에 단면 크기가 호환되는 부호를 후보로 연결하되 부재 위치·부호 매칭은 미확정으로 저장합니다. W1=200 mm, 콘크리트/철근 재료 표기와 상세의 두께·마감 표기 308건도 도면 근거로 보존합니다. 이 기록은 뷰어의 ‘구조 일람표 · 상세 도면 조사’ 및 IFC의 건물 속성 `Pset_DrawingSurvey`에서 확인할 수 있습니다.

외벽 상세의 THK24 로이복층유리와 창호 상세의 THK28 LOW-E PAIR GLASS가 함께 존재합니다. 개별 적용 부위와 개정 일치를 확인하지 않고 모든 창에 하나의 두께를 적용하지 않았습니다. 보조 상세의 반복 삽입/XCLIP 미적용 경고도 있어 표기 빈도는 실물 수량을 뜻하지 않습니다.

EL 근거는 단면의 `layout:Model/8F9D` 블록과 입면 층 기준 텍스트에서 교차 확인했습니다. 층 기준 간격은 천장고나 벽 상단 높이가 아닙니다. 벽·기둥 높이로 사용한 층간 압출은 별도 후보로 기록합니다.

도면 mm를 모델 m로 환산합니다. 공통 기준은 `(32920000, -5730000) mm`, 시트별 X 이동량은 `126150.00007091 mm`입니다. 지하층부터 지붕까지 이 이동량을 각각 제거해 같은 좌표계에 정렬합니다. 다각형에는 1 mm 정밀도 격자를 적용하고, 개구부 경계의 반올림 때문에 바닥이 다시 채워지지 않도록 1 mm 여유를 둡니다.

실/바닥 폐합에는 최대 150 mm의 간극 처리가 들어갑니다. 따라서 원래 벽면 좌표가 정확하더라도 실 경계·면적까지 확정되는 것은 아닙니다. 중정은 CAD의 벽/창호 끝점 연결 후보이며 구조 슬래브 경계를 직접 측정한 결과가 아닙니다.

## 뷰어와 IFC

- 기본 화면은 BIM 모델 검토입니다. 기존 BF 화면은 별도 버튼으로 보존했습니다.
- 층 선택/표시 분리, 벽/지붕 숨김, 실 영역/실명 표시, 미확정 면 표시, X/Y/Z 단면 위치 조절을 제공합니다. 표시 간격은 원본 좌표를 변경하지 않습니다.
- 객체 선택과 강조는 카메라를 초기화하지 않습니다. 전체 맞춤, 선택 확대, 실내 눈높이 시점과 WASD/QE 자유 카메라를 제공합니다. 자유 카메라는 통행 시뮬레이션이 아닙니다.
- 우측에서 층·면적·XY 범위·높이 근거·계단 구성요소·인접 실/벽 후보와 CAD 출처를 확인합니다. 객체 목록에는 종류 필터를 추가했습니다.
- 미확인 문/창을 입체로 보는 옵션은 화면에 **문 2.10 m, 창 2.40 m / 창대 0.90 m의 시각화 가정**임을 계속 표시합니다. 끄면 미확인 높이는 평면으로 표시합니다. 이 가정을 JSON이나 IFC의 확정 치수에 저장하지 않습니다.
- 높이가 입력된 문·창 개구부는 높이 구간에만 벽을 잘라 창 하부와 인방을 보존합니다. 기존 경로용 평면 함수는 유지합니다.
- IFC4에서 벽·기둥·문·창·실·슬래브·지붕·계단·승강기를 구분합니다. 계단의 단/참은 `IfcBuildingElementPart`로 분해하고 계단 객체에 귀속합니다. 재질/색과 `Pset_ArchitecturalEvidence`를 포함하며 미확인 높이는 평면으로 출력합니다.

## 자료 부족 / 도면 불일치

아래 항목은 완료됐다고 표시하지 않습니다.

1. 입면/단면의 누락 XREF와 AEC 프록시: 해당 DWG에 자료가 있어도 현재 변환 결과에 실제 외벽/단면 본체가 충분히 남지 않았습니다. 완전한 입면을 확보하거나 프록시를 표준 객체로 변환한 도면이 필요합니다. 원본은 임의 변환 저장하지 않았습니다.
2. 지하주차장 일부 바닥, PIT, 옥탑 상부: 상세/경계 연결 검토가 필요합니다. 지상 중정을 지하 바닥에 그대로 빼지 않았습니다.
3. 지붕 외곽·단차·파라펫·태양광 및 외벽 상단: 현재 투영 후보를 실제 지붕으로 확정하려면 도면 개정과 입단면 상세가 필요합니다. 조감도에 맞춰 임의 형상을 만들지 않았습니다.
4. 문·창 높이/창대와 개별 일람표 매칭: 창호도를 읽었지만 평면의 블록과 일람표 ID를 확정하지 못했습니다. 공통 높이를 실측처럼 적용하지 않았습니다.
5. 계단: 코어 상세의 `175 × 12EA`와 기준층 간격 4.20 m는 일치합니다. 평면 한 코어는 280 mm, 상세 일부는 300 mm로 불일치합니다. 진행 방향·참·중앙 100 mm 간격은 복원 가정입니다. 3.90/5.40 m 비기준층은 기준층 계단 높이를 복사하지 않고 평면으로 보존했습니다.
6. 실별 경계: 식당/주방 등 공동 경계에 여러 실명이 남는 곳은 미분리 후보입니다. 문을 통한 인접 후보는 확정된 실 연결 또는 BF 통행 연결이 아닙니다.
7. 구조 보, 슬래브 두께·배근·실제 슬래브 개구부: 구조 도면과 일람표를 조사했지만 누락 `s-xref-plan`/`s-xref-section`, 프록시 및 건축 평면과의 부재 위치 매칭을 해결해야 합니다. C3/C4처럼 단면이 같아 크기만으로 구별되지 않는 기둥도 있어 부호 후보를 확정 정보로 바꾸지 않았습니다.
8. 외벽·창호 상세의 유리 24/28 mm 사양: 적용 위치와 개정 관계가 미확정입니다.

## 검증과 결과물

자동 검사: Python BIM/API/IFC 테스트 13개, 기존 CAD 리더 6개, TypeScript 모델/형상/기존 경로/뷰어 표시/저장 보존 테스트 24개를 실행했습니다. TypeScript 및 Vite 빌드도 수행했습니다. 창 하부/인방 보존, 가정 치수의 비저장, 층 분리의 원본 높이 보존, 계단 IFC 단/참 분해, IFC4 EXPRESS, 미확인 실제 모델의 경로 차단을 검사합니다. 저장 검사는 대형 JSON 보존, 기존 저장본 유지, 트랜잭션 중단 시 복구, 저장소를 쓰지 못하는 환경과 용량 오류를 포함합니다. 테스트의 IndexedDB API 구현은 [fake-indexeddb](https://github.com/dumbmatter/fakeIndexedDB)를 사용하며 실제 브라우저 검증과는 구분합니다.

최종 실제 IFC도 별도로 검사했습니다. 2,278개 모델 객체와 238개 계단 구성요소의 전체 형상을 테셀레이션하고, JSON 형상과 월드 좌표 범위·평면 면적·입체 체적을 비교했습니다. EXPRESS 오류 0건이며 좌표 차이는 부동소수점 계산 오차 수준입니다. 558개 평면 객체/구성요소는 미확인 높이를 임의 입체로 바꾸지 않고 유지했습니다. 이는 도면 대비 기둥 단면의 최대 편차 약 0.64 mm와는 다른 검사입니다.

로컬 웹 페이지·상태 API·최신 모델 API·6개 층의 도면 이미지 모두 HTTP 200을 확인했습니다. API 모델은 로컬 BIM JSON과 일치합니다.

최신 서버의 IFC 다운로드 API도 실제 모델로 호출했습니다. 기둥 일람표/상세 기록을 포함한 `Pset_DrawingSurvey`, 창호 프로파일 272개, 계단 구성요소 238개가 포함됨을 확인했습니다. 최종 정적 빌드의 모델 데이터에도 같은 구조 도면 근거가 들어갑니다.

`prepare_project` 전체 절차도 다시 실행해 도면 분석 캐시 확인 → 모델 재생성 → 도면/3D 이미지와 IFC 생성 → 최종 IFC 전체 검증의 완료를 확인했습니다. 재생성한 로컬 모델·정적 모델·API 모델의 객체 형상과 계단 구성요소도 일치합니다. 일반 빌드와 이용자용 `/bim-check/` 경로 빌드를 수행했으며, 후자는 HTML·모델·설정·정적 자산·기존 Worker URL의 HTTP 검사를 통과했습니다.

`bf_bim.verify_model`은 원본 16개 DWG의 SHA-256, 모델의 CAD ID 참조, 기둥 단면 좌표 편차(1 mm 이하), 지상 중정/코어와 바닥의 겹침, 계단 구성요소, 문·창의 미확인 높이를 검증합니다. 자동 형상 검증은 모델 전체와 실물의 일치 인증을 뜻하지 않습니다.

## 실행과 재생성

```powershell
.\start.ps1
```

`http://127.0.0.1:5173/`에서 실제 모델을 엽니다. 로컬 Python 서버가 없으면 `web/public/models/project.json`의 동일한 모델을 읽습니다. 기존 브라우저 저장본이 새 생성 모델을 가리지 않도록 목록에 보존합니다. 커진 BIM JSON과 이전 저장본을 함께 저장할 수 있도록 새 저장은 IndexedDB의 단일 트랜잭션으로 처리합니다. 기존 localStorage 키는 그대로 두고 읽으며 최초 이전 저장본도 보존합니다. IndexedDB를 쓸 수 없는 환경에서는 기존 저장 방식으로 복귀합니다.

```powershell
.\.venv-cad\Scripts\python.exe -m bf_bim.prepare_project
.\.venv-cad\Scripts\python.exe -m bf_bim.publish_model
.\.venv-cad\Scripts\python.exe -m bf_bim.validate_ifc
.\.venv-cad\Scripts\python.exe -m pytest tests -q
.\.venv-cad\Scripts\python.exe -m unittest discover -s cad_reader/tests -v
npm.cmd test --prefix web
npm.cmd run build --prefix web
```

`publish_model`은 로컬 정적 JSON만 갱신합니다. 원격 저장소 push나 실제 사이트 배포를 실행하지 않습니다.

사용자가 요청한 공개 배포는 `.github/workflows/pages.yml`이 담당합니다. `VITE_VIEWER_ONLY=true`, `VITE_BASE_PATH=/energy-center-bim-bf/`로 빌드하며 실제 배포 경로의 자산과 모델을 검사합니다. 공개 주소는 [에너지센터 BIM 뷰어](https://ohan9i.github.io/energy-center-bim-bf/)입니다. 원본 DWG·로컬 분석 캐시·가상환경은 기존 Git 제외 규칙을 유지합니다.
