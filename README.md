# BIM 기반 BF개선

UI/UX 개선은 [작업 화면과 검증 방법](docs/UI_UX_REFINEMENT.md)에 정리했습니다. 상단에서 BIM 모델과 BF 경로 탐색을 전환하고, 객체 탐색·속성 패널을 접거나 펼칠 수 있습니다. 표시 설정과 단면·층 분리는 뷰어 도구에서 열며, 모바일에서는 하단 패널을 사용합니다.

최신 BIM 개선은 [조립체 개선 결과와 미완성 항목](docs/BIM_ASSEMBLIES.md)에 정리했습니다. 모든 층의 추출 바닥 영역에 두께 있는 구조 슬래브와 마감을 추가하고, 문틀·창틀·샤프트·계단 접합 및 IFC 개구부 관계를 개선했습니다. 도면에서 확정하지 못한 두께/높이는 수정 가능한 임시 치수로 명시합니다. 구조 보와 일부 외곽/상부 형상은 자료 부족으로 미완성입니다.

현재 개발 우선순위는 **실제 DWG 기반 BIM 모델의 정확도와 완성도**입니다. 로컬 기본 모델은 **지하 1층·지상 1~4층·지붕 후보**를 포함하며, 개별 벽체·기둥·문·창호·실·계단 조립체와 도면 출처를 제공합니다. 층 분리, 벽/지붕 숨김, 단면, 실 선택, 실내 자유 시점을 사용할 수 있습니다. BF 알고리즘과 예제 데이터는 보존하며 이번 작업에서 확장하지 않았습니다. 구현 내용과 남은 자료는 [BIM 정밀화 결과](docs/BIM_REFINEMENT.md)를 참고하세요.

공개 홈페이지: **https://ohan9i.github.io/energy-center-bim-bf/**

GitHub 저장소: https://github.com/ohan9i/energy-center-bim-bf

공개 홈페이지는 지하 1층·지상 1~4층·지붕 후보와 BIM 검토 뷰어를 제공하는 이용자용 빌드입니다. `main`의 웹 변경사항은 GitHub Actions를 통해 Pages로 배포합니다. DWG 업로드·설계자 편집·IFC 출력은 아래 로컬 실행 환경에서 제공합니다.

## 바로 실행하기

프로젝트 폴더의 PowerShell 터미널에서 실행합니다.

```powershell
.\start.ps1
```

브라우저에서 `http://127.0.0.1:5173/`를 엽니다. Python 서버가 실행 중이면 전체 출처 정보를 가진 실제 도면 모델을 자동으로 불러옵니다. 서버가 없으면 공개용 실제 모델을 불러옵니다. 종료는 `.\stop.ps1`입니다. 스크립트가 시작한 프로세스만 종료합니다.

새 PC 또는 의존성이 없으면 Node.js 24, Python 3.12를 설치하고 다음을 실행합니다.

```powershell
py -m venv .venv-cad
.\start.ps1 -Install
```

스크립트 실행 정책으로 실행이 차단되는 환경에서는 정책을 바꾸지 않고 아래 두 명령을 **각각 별도 터미널**에서 실행할 수 있습니다.

```powershell
.\.venv-cad\Scripts\python.exe -m uvicorn bf_bim.app:app --host 127.0.0.1 --port 8000
```

```powershell
cd web
npm.cmd run dev
```

## 실제 도면으로 생성한 결과

사용자 선택에 따라 상세 형상이 남은 도면 묶음의 지상 1·2층을 사용했습니다.

| 입력 DWG | 사용한 정보 |
| --- | --- |
| `에너지-건축도면/A04-001~008 평면도.dwg` | 실제 mm 단위 좌표, 벽면, 기둥, 문 회전호, 계단 블록, E.V 표기, 실명 |
| `에너지-건축도면/A04-021~026 단면도.dwg` | 1층 EL +37.70, 2층 EL +41.90, 층간 높이 4.20 m |

원본 DWG는 임시 복사본으로 변환하며 원본 해시 일치를 확인했습니다. 모델 Z 기준은 1층을 0 m로 이동한 상대 높이입니다. 실제 2층 도면의 시트 X 이동량 126150.00007091 mm를 제거해 두 층의 기둥·코어 위치를 정렬했습니다.

생성 파일은 공개 빌드에 포함되지 않는 `cad_output/`에 있습니다.

| 파일 | 내용 |
| --- | --- |
| `energy-center-model.json` | 웹 모델·원본 객체 ID·자동 추정 근거·미확인 속성 |
| `energy-center.ifc` | IFC4 모델, m 단위 형상과 CAD 출처 속성 |
| `energy-center-preview.png` | 실제 도면 기반 1·2층 모델 미리보기 |
| `detailed-first.png`, `detailed-second.png` | 실제 DWG의 층별 선형 도면 대조 이미지 |
| `energy-center-report.json` | 추출 객체 수, 층 분리 범위, 층 높이 근거 |
| `actual-floorplans.json` | 기존 리더의 전체 추출 결과; 약 527 MB |

높이/두께가 미확인인 바닥·문·승강기는 IFC에 두께 없는 평면 형상으로 출력해 위치를 보존합니다. IFC4 형식 검사 통과와 건축/BF 검토 완료는 별개입니다.

재생성 명령:

```powershell
.\.venv-cad\Scripts\python.exe -m pip install matplotlib==3.11.2 pillow==12.3.0
.\.venv-cad\Scripts\python.exe -m bf_bim.prepare_project
```

프로젝트별 추출기는 **이 도면의 승인된 배치 범위에 맞춘 어댑터**입니다. 다른 DWG에는 웹의 일반 CAD 업로드 기능을 사용하세요. 원본이 변경되면 분석 캐시를 갱신하며, 해시가 같으면 캐시를 재사용합니다.

## 웹 사용 순서

1. 건축물 목록에서 실제 도면 모델 또는 `공간이음 교육관 · 2층 예제`를 선택합니다.
2. `3D`/`평면`, 층 선택으로 모델을 확인합니다. 실제 모델의 `CAD` 버튼은 원본 선형 도면을 표시합니다.
3. 설계자 모드의 객체 목록에서 요소를 선택해 유효폭·단차·경사·가동 여부를 입력합니다. 값 변경 시 확인 상태와 기존 경로가 무효화됩니다.
4. 기하학·입력 속성을 검토한 다음 확인 체크를 합니다. 이 체크는 사용자의 검토 기록이며 자동 인증이 아닙니다.
5. `위치 · 형상 · 분류 편집`에서 요소 JSON을 수정할 수 있습니다. `요소 추가`·`요소 제외`, `층 · 공간 · 연결 편집`도 제공합니다.
6. 출발지·목적지·이용자 유형과 세부 조건을 선택해 경로를 탐색합니다. 이용자 모드는 같은 모델을 사용합니다.
7. `저장`은 현재 브라우저의 로컬 저장소, `JSON`은 파일 저장, `IFC`는 로컬 Python 서버를 통한 IFC4 내보내기입니다.

실제 도면 모델은 **확인 필요**로 시작합니다. 바닥 경계·중정·문 유효폭·단차·시설 연결을 확인하지 않은 채 실제 이용 가능한 경로를 만들지 않습니다. 예제는 테스트 치수가 명시되어 있어 일반 보행자는 계단, 휠체어 이용자는 승강기 경로를 비교할 수 있습니다.

## 구현 범위

### 구현 완료

- 원본 보존 DWG/DXF 읽기, 기존 리더 재사용, 레이어 목록·단위·블록 전개·외부 참조 경고.
- 실제 프로젝트 1·2층 분리, 벽면·기둥·문/승강기/계단 후보와 실명 좌표 추출, 단면도 근거 높이 정렬.
- 3D/평면 모델 표시, 층 선택, 객체 선택/강조, 도면 대조, 객체 JSON 편집·추가·제외.
- 브라우저 Web Worker에서 격자 A* 경로 탐색. 이동 선분별 장애물 충돌·이동 몸체 여유폭 검사, 문 개구부 처리, 층간 연결.
- 일반 보행자·휠체어·보행약자별 사용자 조건 조정. 미확인/불가 요소 제외, 경로 없음, 거리·시간·제외 원인 표시.
- JSON/IFC4 출력, 원본 CAD 식별자·사용자 수정 출처 유지, 모델 수정 시 경로 갱신.
- 사용자 조건 JSON 설정, 3단계 검토 상태, 설계자/이용자 UI, 반응형 CSS, WebGL 불가 시 SVG 평면 대체.
- GitHub Pages 하위 경로 빌드 설정 및 수동 실행 GitHub Actions 구성.

### 부분 구현 / 실제 도면에서 추가 검토 필요

- 실제 프로젝트의 벽체: 평행한 벽면 사이 간격을 이용해 벽체 후보를 만듭니다. 짝이 없는 면은 폭 1 cm의 **미확정 면 표시**이며 실제 벽 두께가 아닙니다.
- 실제 바닥: 벽면 끝점의 오목 외곽으로 생성한 영역 후보입니다. 중정·외부공간·슬래브 개구부는 직접 편집해야 합니다. 면적은 인증/수량 산출값이 아닙니다.
- 실제 문: 회전호의 위치와 반지름으로 개구부 후보를 생성합니다. 문짝 크기·블록 이름은 유효 통과 폭으로 간주하지 않습니다.
- 실제 승강기/계단: 실명·블록 외곽 후보를 표시하며, 가동 상태와 층간 연결을 확인하지 않아 실제 모델의 `links`는 비어 있습니다.
- 실제 벽·기둥 높이는 단면도 층간 높이를 이용한 단순 압출입니다. 천장고·실제 벽 상단 높이·슬래브 두께의 확정값이 아닙니다.
- 일반 CAD 업로드: 직선, 직선으로 구성된 닫힌 폴리라인, 원형 기둥을 모델링합니다. 문 블록/AEC 의미·곡선 벽/HATCH 영역을 완전 자동 해석하지 않습니다. 한 번에 한 층을 처리하며 다층/도면 묶음 분리는 프로젝트 어댑터 또는 수동 편집을 사용합니다.
- 실제 모델의 BF 경로는 현재 미검증입니다. 2층 예제의 경로 성공을 실제 건물 통행 검증으로 해석하면 안 됩니다.

### 외부 프로그램 필요

DWG는 [ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter)가 필요합니다. 현재 작업 폴더의 `.tools/oda/runtime/ODAFileConverter.exe`를 기존 리더가 탐색합니다. 없으면 오류를 표시하며 DXF 업로드는 가능합니다.

```powershell
.\.venv-cad\Scripts\python.exe -m cad_reader doctor
```

## BF 판단과 경로 알고리즘

`web/public/rules.json`은 기준 ID·평가 항목·대상·단위와 프로필 수치, 근거 설명·적용일·검증 상태를 관리합니다. **기본값은 공식 BF 인증 수치가 아닌 사용자 정의 이동 조건**입니다. 한국장애인개발원 [BF 매뉴얼 목록](https://www.koddi.or.kr/data/manual01.jsp)에서 2025 해설서 게시물을 확인했으나 개별 수치·조항·현행 법령 적용성 검증은 완료하지 않았습니다.

이동 가능한 바닥 다각형을 0.25 m 간격으로 격자화하고, 모든 간선을 바닥 경계·벽·기둥·미확인 구간과 대조합니다. 몸체 폭의 절반을 선분 주변에 확보합니다. 문 주변을 제외한 구간에서는 요청 통로 여유폭도 적용합니다. 문 유효폭·단차·경사·승강기 가동 조건을 만족하지 않으면 해당 구간을 제외합니다. 문 접근부는 몸체 여유폭과 문 속성 검사를 적용하는 초기 모델이며 정식 BF 활동공간 검증이 아닙니다.

층간 연결이 XY를 유지하면 수평 유클리드 거리를 A* 휴리스틱으로 사용합니다. 임의 위치의 층간 연결은 과대 추정을 피하기 위해 0 휴리스틱을 사용합니다. 이동 거리와 시설 대기시간을 반영한 비용을 최소화하며 계단 이용 부담 가중치를 조정할 수 있습니다. 길이는 경로의 실제 간선 길이 합, 시간은 거리/속도 + 승강기 대기시간입니다.

검토 상태는 현재 조건에 대한 `통과 가능`, `통과 불가능`, `추가 확인 필요`입니다. 공식 BF 인증을 대체하지 않습니다.

## 구성과 API

```text
cad_reader/             기존 DWG/DXF 추출 모듈 (보존)
bf_bim/
  schema.py             m 단위 모델 스키마, ID/참조/다각형 검증
  cad.py                일반 CAD 레이어 분류·BIM 변환
  project_model.py       실제 프로젝트 1·2층 변환 어댑터
  geometry.py           문 개구부를 반영한 공통 IFC 평면 형상
  ifc_export.py         IFC4 공간 계층·단위·형상·출처 속성
  app.py                로컬 FastAPI
web/src/
  model.ts              브라우저 모델 스키마
  geometry.ts           다각형 연산·연속 선분 충돌 검사
  evaluation.ts         사용자 이동 조건 평가
  navigation.ts         격자 그래프·A*/Dijkstra
  route.worker.ts       계산용 Web Worker
  Viewer.tsx            Three.js 뷰어 / SVG 대체
  App.tsx               모드·편집·업로드·경로 안내
tests/                  Python 검증
web/tests/              브라우저 경로 알고리즘 검증
.github/workflows/      Pages 배포 설정
```

API 문서는 `http://127.0.0.1:8000/docs`입니다. CAD 세션은 메모리 저장, 1시간 만료, 최대 4개이며 서버 재시작 시 사라집니다. 파일은 50 MB, 전개 객체는 100,000개까지 처리합니다. 상한/외부 참조 경고를 확인해야 합니다. 기존 ODA 전역 설정 변경은 락으로 직렬화합니다. 업로드의 XREF는 별도 첨부되지 않으므로 내용 추출이 되지 않습니다. `cad_output/`와 원본 DWG는 공개 저장소/정적 빌드에 포함하지 않습니다. 공개용 실제 모델은 `web/public/models/project.json`에 별도로 보관하며 로컬 절대 경로와 전체 분석 출처를 제외합니다.

## GitHub Pages

Python·ODA·IFC 출력은 로컬 처리 기능입니다. GitHub Pages에서는 뷰어·이용자 경로 탐색이 정적으로 실행됩니다. `VITE_VIEWER_ONLY=true` 빌드는 설계자 UI를 노출하지 않으며, 방문자가 불러온 JSON은 방문자 브라우저에서만 처리됩니다. 서버 없는 브라우저의 경로 계산은 예제와 동일한 알고리즘입니다.

`.github/workflows/pages.yml`은 `main`의 웹 코드 변경 시 자동 배포하며 GitHub Actions에서 수동 실행도 가능합니다. Pages의 빌드 소스는 GitHub Actions입니다. 프로젝트 저장소는 `/<저장소명>/`으로 빌드합니다. `<계정>.github.io` 루트 저장소나 사용자 도메인은 base를 `/`로 조정해야 합니다. 사용자의 공개 요청에 따라 `ohan9i/energy-center-bim-bf` 저장소와 Pages를 사용합니다.

실제 공개 모델을 갱신할 때는 `python -m bf_bim.publish_model`로 로컬 모델에서 공개용 JSON을 생성하고 변경 내용을 확인한 뒤 커밋합니다. 원본 DWG, ODA 프로그램, 가상환경, 실행 로그, 약 527 MB의 원시 분석 JSON은 Git에서 제외합니다.
